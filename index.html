Channel Integrations: Slack

Primary channel for GenHealth deployment

Configuration

  • Workspace: genhealthai.slack.com
  • Mode: Socket Mode (no public webhooks needed)
  • Bot token: xoxb-* (channels, messaging, reactions)
  • App token: xapp-* (Socket Mode connection)

Access Control

  • DM allowlist: Specific users can message bot directly
  • Group allowlist: Private channels/groups the bot participates in
  • Public channels: requireMention: true (bot only responds when @mentioned)

Key Features

  • Message sending, editing, deletion
  • Reactions (emoji responses)
  • Thread support
  • Rich formatting (markdown, attachments)
  • Search via user token (search.messages API)
Important: The bot token has limited read scopes. For reading channel history, use the user token + search.messages API.

Task Management: Lokiban

Architecture

  • Backend: SQLite database + Express API (port 18790)
  • Frontend: Web dashboard (Tailscale port 8443)
  • PM2 process: kanban-server
  • Sync: Auto-exports to brain/tasks.md (Obsidian-compatible)

Kanban Lanes

Flow: Capture → P2 → P1 → P0 → In Progress → Done → Later

API-Driven Workflow

Critical rule: NEVER edit tasks.md directly. Always use the API. SQLite is source of truth.
Action Endpoint
Create task POST /api/capture
Update task POST /api/task/{id}
Move task POST /api/task/{id}/move
Complete task POST /api/task/{id}/complete

Circuit Breakers & Safety

  • Auto-disable after 3 consecutive errors — Prevents runaway failures
  • Dedup check — Don't create duplicate failure tasks
  • Quiet hours (23:00-07:00) — No messages unless urgent
  • PM2 auto-stop — After 10+ restarts, assume broken and stop
Overnight work: Autonomous session has full API access but operates in "review mode" — outputs go to designated folders for Mike's review in the morning.

Sub-Agent Architecture

Design Philosophy

Rule: If a task takes >30 seconds of active work → spawn a sub-agent.

Main session (Opus) handles conversation and decisions. Sub-agents (Sonnet) handle execution.

How It Works

  • Main session spawns isolated Sonnet 4.5 sessions for heavy work
  • Each sub-agent gets clear task description, context files, success criteria
  • Output saved to /output/{agent}/{task-slug}/
  • Completion is push-based (auto-announces to main agent)

Dispatch System

agents/dispatch.sh — Checks Lokiban for tasks assigned to specific agents, spawns sub-agents automatically

Limits

Type Max Concurrent
Main tasks (P0/In Progress) 4
Sub-agents (total) 8

Security & Safety

Credential Management

Never hardcode keys. All credentials stored in config files:

  • ~/.config/attio/api_key
  • ~/.config/slack/genhealth_user_token
  • ~/.config/himalaya/config.toml
  • ~/.config/cloudflare/api_token
  • etc. (see TOOLS.md for full list)

Access Control

  • Gateway: Loopback-bound (127.0.0.1), only accessible via Tailscale
  • Tailscale: Private network, funnel only for webhooks
  • Slack: DM/group allowlists, requireMention in public channels
  • iMessage: Allowlist-based DM policy

Data Handling

  • MEMORY.md: Only loaded in main session (1:1), never in group chats
  • No exfiltration: Private data stays local unless explicitly shared
  • trash > rm: Recoverable deletion by default

Circuit Breakers

  • Cron jobs auto-disable after 3 consecutive failures
  • PM2 processes auto-stop after 10+ restarts
  • Context handoff at 70%+ token usage (prevents truncation)

  3. Install OpenClaw globally via npm

  1. Create workspace directory (/home/genhealth/assistant or similar)

Phase 3: Integrations (Week 2)

  2. Set up credential storage (~/.config/ paths)
  3. Test message send/receive via Slack
  4. Configure minimal cron jobs (digest, heartbeat, backup)

Phase 4: Testing & Iteration (Week 3+)

  1. Test sub-agent spawning and output delivery
  2. Adjust cron frequency based on team needs
  3. Add custom skills as needed (CRM, internal tools)
  4. Monitor, tune, document edge cases
